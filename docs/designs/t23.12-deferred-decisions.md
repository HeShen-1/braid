## 企业 SSO Web 入口（F15）

决策记录：[D-2026-10-16-t2312-web-sso](../DECISIONS.md#d-2026-10-16-t2312-web-sso)，
状态：**待裁决**。D-t111 当时将 Web fragment 承接延期到 T14；当前仍没有
SPA 消费面，本记录接续该延期指针，不把历史文字当作已实施。

| 当前事实 | 代码证据 |
| --- | --- |
| OIDC 后端已实现；配置完整才装配，两条路由在 provider 注入后才挂载 | [组合根](../../cmd/api/main.go#L189)、[路由](../../internal/api/server.go#L312) |
| 登录起点发 302，回调签发 Bearer，成功返回 JSON `loginResponse`，不是 SPA 导航 | [起点](../../internal/api/oidc.go#L75)、[回调](../../internal/api/oidc.go#L139) |
| 当前登录页只提交用户名/密码；客户端调用 POST login，认证态通过 `session.start` 建立 | [LoginView](../../web/canvas/src/LoginView.tsx#L27)、[API](../../web/canvas/src/api.ts#L341)、[auth](../../web/canvas/src/auth.tsx#L19) |

| LDAP 已实现且配置后替换凭证身份源，现有表单可经相同 POST login 进行 LDAP 核验；它不是 OIDC 重定向登录 | [LDAP 装配](../../cmd/api/main.go#L158)、[凭证核验](../../internal/api/login.go#L170) |

具体缺口：OIDC 入口的可发现性与启用态呈现、JSON 回调到 SPA 的安全会话交接、
登录后返回原页面及取消/失败/过期时的用户出口尚未集成。
仅加一个跳转按钮仍会在回调 JSON 处停止；后端单测或 LDAP 表单可用都不能证明
OIDC Web 旅程完成。部署模板透传边界已由 T23.11 登记，本票不再修改。

**唤醒触发器**：出现明确要求“从 braid 登录页经企业 IdP 登录并回到控制台”的
接入/验收需求，或用户决定交付该 Web 旅程；届时先对上述 D- 作出具体确认。
普通 UI 修复、已有 OIDC 配置或本票闭环不自动触发实施。

| 候选方向（均未批准） | 取舍 |
| --- | --- |
| 继续保留 JSON 回调与现有凭证表单 | 当前有效行为；无协议变化，但 OIDC Web 缺口继续保留 |
| 保留现有 API，另设计兼容的 Web 会话交接 | 需要裁定入口启用态来源、临时交接机制、同源返回目标与失败出口；增加实现与安全验证面 |
| 改变现有回调响应为浏览器导航 | 需明确 API 兼容或破坏策略；原 D-t111 的 JSON 契约必须显式修订，不能由按钮改动顺带生效 |

**后续实施边界**：确认具体方案后另排实施；明确哪些现有 D- 被修订。
默认保留 Bearer + `sessionStorage`、本地账号锚定、租户/角色/作用域与 token 绑定、
OIDC state/nonce/PKCE 及既有登录审计错误分层。若需要改变这些条款、配置、DTO、
身份映射或迁移，须在裁决中逐项列出；本票没有该授权。
验收至少分开记录 provider 未配置/已配置、正常返回/深链返回、取消/协议失败/
本地停用等旅程与凭据不进 URL/日志/缓存的检查；工程 IdP 与真实企业 IdP 证明分开，
不把旧后端测试改写为真实企业登录通过。

## execution 终态审计事件（F66）

决策记录：[D-2026-10-16-t2312-execution-terminal-audit](../DECISIONS.md#d-2026-10-16-t2312-execution-terminal-audit)，
状态：**待裁决**。D-t26 的早期范围排除了 execution 迁移事件；之后已按任务加入
triggered、rolled_back、cancelled。本记录保留这些历史，不将早期范围误写为当前全集。

| 当前事实 | 代码证据 |
| --- | --- |
| 词表已有 `execution.triggered`、`execution.rolled_back`、`execution.cancelled`；没有 SUCCEEDED/FAILED 对应词 | [常量与闭集](../../internal/audit/writer.go#L126) |
| 成功收口在锁定事务内调用 `FinishExecution(SUCCEEDED)`，之后记录进程日志 `execution.succeeded` | [finishIfDone](../../internal/scheduler/sched.go#L1068) |
| scheduler 失败收口、reaper 的 PENDING 超时/attempt 耗尽/审批超时失败均写执行状态和日志，未发执行失败审计事件 | [failExecution](../../internal/scheduler/sched.go#L1502)、[PENDING 超时](../../internal/reaper/scan_exec.go#L96)、[attempt 耗尽](../../internal/reaper/scan_attempt.go#L516)、[审批超时](../../internal/reaper/scan_approval.go#L349) |
| `FinishExecution` 是状态 CAS helper，保存终态、输出/错误与完成时刻，本身不写审计 | [wfcas](../../internal/engine/wfcas.go#L86) |
| 取消已同事务写 `execution.cancelled`，含触发前状态和取消节点数；不能再称“所有终态都没有事件” | [取消事务](../../internal/scheduler/cancel.go#L239)、[payload](../../internal/audit/payload.go#L238) |
| 前端消费真实事件原码及标签，未伪造执行成功/失败事件 | [事件呈现](../../web/canvas/src/ExecutionEvidence.tsx#L198) |

具体缺口：只读取审计链的消费者不能取得执行成功/失败的专属终态事实；
执行详情状态、节点事件、进程日志和审计事件是不同证据层，不能相互冒名。
PENDING 超时甚至没有对应失败节点可供反推。已有审计分页/轮次消费由 T23.9
交付，本票不重做该消费面，也不把日志词注册成新事件。

**唤醒触发器**：明确出现仅依赖审计链判定执行成功/失败的导出、合规消费或验收
要求，或用户要求逐轮终态事件；先对上述 D- 确认覆盖状态及事件语义。
调整中文标签或展示已有执行状态不构成扩词授权。

| 候选方向（均未批准） | 取舍 |
| --- | --- |
| 保留当前词表，由执行详情提供终态 | 当前有效行为；审计链单独消费的缺口保留，需向消费者明确边界 |
| 为成功、失败各加专属事件 | 直读结果；需裁定原码、payload、actor、所有收口来源及与现有取消事件的关系 |
| 用一个通用终态事件携带结果 | 统一消费形状；需裁定是否纳入 CANCELLED，以及保留/关联现有 `execution.cancelled` 后怎样避免双计数 |

**后续实施边界**：确认词表及 payload 前不新增事件、状态枚举、配置或 DTO。
实施方案须覆盖上表全部收口来源，明确 CAS 胜者同事务写入、重复收口零重复事件、
并发回滚后的轮次归属、actor/trace 世系及自由文本脱敏/错误字段边界。
保持 audit_log append-only、节点 CAS、既有锁序/fence 与 engine 不内嵌审计的分层；
如确需 engine、迁移或新轮次字段，另列明确 D- 与相应人工合并门。
验收需包含成功、普通失败、PENDING 超时、reaper 耗尽、审批超时失败、
取消、重复收口、回滚再终态，并检查无虚构历史回填；本票未执行这些新增能力验收。
