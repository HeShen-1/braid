## 验证、合并与远程分支删除

1. 开工前查 ARCHITECTURE → ROADMAP → 对应 issue；检查同名分支、worktree、assignee。当前建议首波槽位 .6=1、.11=2，主仓=0；均需现场复核，禁止哈希自动分配。
2. 按仓库完成三件套及任务适用专项门；前端源码改动必须 vitest、dist 同提交、正式漂移门和对应浏览器旅程。真栈、组件账号、工程桩、真实模型分别举证。文档任务逐条核对指令与实际代码/配置，历史交付计数保持原样。
3. 固定端口真栈/e2e 共用 `/tmp/braid-m23-validation.lock`，外层 `flock -n -o` 覆盖起栈→验证→收栈，锁内不再嵌套同一把锁。测试数据、项目名、schema 和槽位独立；活进程联调仅主仓，不操作现有 dev/prod 数据或进程。
4. push → draft PR（`Closes #N`）→ 本地读取实际 `gh pr diff` 做独立审查并回贴 findings → CRITICAL/HIGH 清零。新建 PR 用 Codex `attach_artifact` 关联当前 chat。
5. 合并前核对最终 head、base、最新 master 关系和实际 diff；`gh pr checks` 必须原生退出 0，lint/test/gitleaks/promtool/helm/web/e2e 七项均为 COMPLETED/SUCCESS，不能只看 JSON 中 success 字样或复用旧头绿灯。变更后重新确认受影响证据。
6. 常规任务按仓库执行 merge commit；触及 migrations、engine、go.mod、CI、AGENTS.md 等保护面时仍留用户在 GitHub 人工合并。同步最新 master，并确认对应 issue 已闭环。
7. **每次远程任务完成并合入后，核验对应远程分支已删除。** 仓库 `delete_branch_on_merge=true` 已开启；若自动删除未生效，确认 PR 已合并、该分支无其他 open PR、不是默认/保护分支，且远端 tip 等于已合并 PR head、已包含于最新 master，才按该 SHA 条件删除。tip 已变化就保留分支并查明新增工作，禁止无条件强删。
8. 分支删除后用 `git ls-remote --heads origin refs/heads/<branch>` 确认不存在，再 `git fetch --prune origin`。保留本地分支、worktree、失败日志与验证记录；清理本地目录需单独的任务依据。
