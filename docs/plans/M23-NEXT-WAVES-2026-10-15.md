## 验证、PR 与收尾

1. 开工按 ARCHITECTURE → ROADMAP → 本任务 issue 读取；检查 assignee、本地/远端同名分支、worktree、进程及手工槽位。取最新默认分支，不回退到本文历史 SHA。每个新树独立 .handoff/.testenv/node_modules/schema，不覆盖旧工作。
2. 按仓库完成三件套 `go test ./...`、`go vet ./...`、`golangci-lint run` 与任务专项门。前端改源码必须 vitest、重建 dist 同提交、正式漂移门和对应浏览器旅程；文档逐条对拍实际事实。真栈、组件账号、工程桩、真实模型及陌生人发现测试分别说明证据边界。
3. 固定端口真栈/e2e 共用 `/tmp/braid-m23-validation.lock`，外层 `flock -n -o` 覆盖起栈→验证→收栈，锁内不再嵌套同锁。数据、Compose project 和槽位独立；活进程联调只在主仓，只回收本任务已核验身份的资源，不操作既有 dev/prod 数据或进程。
4. 两个前端分支各自构建自己的产物。同 checkout 的 build 与 Go embed 测试串行；后合入分支基于最新 master rebase、完整重建 dist、重跑受影响验证和独立审查/CI，禁止拼接散列产物。
5. push → draft PR（`Closes #N`）→ `attach_artifact` 关联 → 本地独立审查实际 `gh pr diff`，findings 回贴 PR。按仓库做六视角审查并清零 CRITICAL/HIGH；修复后的最终候选与证据须对应。
6. 合并前重查准确 head/base、最新 master 关系、实际 diff 及未解决审查；原生 `gh pr checks` 退出 0，lint/test/gitleaks/promtool/helm/web/e2e 七项均 COMPLETED/SUCCESS。不能用旧头绿灯、JSON success 字样或代理自报替代。常规任务按 match-head 执行 merge commit；migrations、engine、go.mod、CI、AGENTS 等保护面仍由用户 GitHub 人工合并。
7. 合并后主仓 ff 同步并核对 issue 闭环，**删除并核验对应远程任务分支**。自动删除未生效时，先确认 PR 已合并、无其他 open PR、非默认/保护分支、tip 精确匹配已合并 head 且为最新 master 祖先，再按该 SHA 条件删除；tip 增长则保留并查明。之后 `ls-remote --heads` 证空及 `fetch --prune`。
8. 本地 worktree 在任务已完成、合并包含关系与干净状态确认、独有交接/配置/证据已归档后可按用户本次授权删除；未完成、有新增提交或未提交内容的树保留。失败记录与本地备份引用保留，不无条件强删。完成当前波次即停止扩展，更新交接供下一轮。
