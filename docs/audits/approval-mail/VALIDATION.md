# 审批邮件链接与时长修复验证

日期：2026-11-09；基线 `master` 为 `8fb5a79463d15acb64ee478403c1b9504f97eac3`。本次只修复邮件超时时长显示和审批通知旧链接的 SPA 承接；不更改通知发送、审批权限或调度策略。

## 问题与修复

先前隔离真栈测试确认：0.1 小时超时邮件显示“0 小时”，邮件链接进入工作流页而非对应审批详情。本次保留已锁定的 `/executions/<id>/approvals/<node>` 邮件链接契约，在认证保护下承接至现有 `/approvals/<id>/<node>` 页面；已发出的同格式链接也可使用。

邮件时长以 12 位有效数字展示，避免 Duration 转换产生难读的浮点尾数。合法范围 0.1–2160 小时的显示舍入误差至多约 18 微秒，不声称任意精度无损。

- `npm --prefix web/canvas test`：34 文件、428 项通过；新增路由测试覆盖已登录、未登录先登录后返回。
- 独立 MySQL 的单独测试 schema 在 `BRAID_TEST_REQUIRE_STACK=1` 下执行 `go test ./internal/notify -count=1 -v`，真 MySQL 通知集成测试通过。小数表驱动覆盖 Duration 往返的 0.1、0.25、0.29、1.25、24.125、24.123456789、72 和 2160 小时。
- `go test ./...`、`go vet ./...`、`golangci-lint run` 通过；本地全量 Go 测试含缓存且默认集成栈不可达，有跳过项，不当作全量真栈验证。通知包真 MySQL 以单独测试为准。
- 前端构建通过，独立重建目录与入库 dist 逐文件一致；最终 CI 与提交后 HEAD 一致性以 PR 检查为准。
- 独立 MySQL、Redis、API、relay、worker、reaper 和只监听本机回环的 SMTP 测试接收器组成真实链路，邮件地址仅用虚构 `example.invalid`，不转发、不接入真实人员。审批期限 0.1 小时，实际等待 6 分钟；扫描间隔设为 2 秒，未修改系统或数据库时间。

## 边界

SMTP 接收器是本机测试服务，不代表外部服务商或真实人员邮箱已送达；真实浏览器使用 Chromium 模拟窄屏，不等同真实手机。未测试或修改 IM 卡片正文；多人部分发送失败后的重复通知及已投票人是否仍接收属于既有边界。测试后隔离栈、测试端口和令牌已清理，原预览服务未重启。
