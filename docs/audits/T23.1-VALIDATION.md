# T23.1 跨轮终态与旧任务认领验证

任务定义:ROADMAP M23 / issue #230。修复基线:`f8ba985`；原复核基线 `7eefd84`。本次只修 scheduler/worker 的事务边界及对应测试，不改变状态、DDL、外部幂等键或业务轮次语义。

## 机制

- `finishIfDone` 在独立事务中先执行租约 fence，再复用 `lockAllRows` 的逐节点锁序，读取终态/输出并在同一事务调用 `FinishExecution`。不能用另一个按数据库 collation 排序的扫描替代既有 Go 节点序。
- `claimAttempt` 在 fence 后锁定节点，把活态、`attempts_base`、输入快照与 attempt 插入放在同一事务。重复 INSERT 撞键释放锁后，接管事务重新锁节点并复核资格，再锁 attempt、刷新心跳。
- 资格/状态读取或事务提交失败停止接管；仅已完成资格判定后的心跳刷新失败保留原尽力语义。已认领提交的在飞调用仍按现有取消协议处理，不承诺撤销外部副作用。

## 真栈复现与回归

验证栈是临时 `braid-t231-test`：MySQL 8.0 / Redis 7.4，端口 13306/16379，tmpfs；已核实与现有 dev/prod 不共端口、数据卷。`BRAID_TEST_REQUIRE_STACK=1` 强制真跑。

| 交错/错误面 | 修复前观察 | 修复后判据 |
|---|---|---|
| 旧终态读取后，回滚提交新轮 | `status=SUCCEEDED old_output=true`，新轮节点仍在执行 | 新轮保持 RUNNING，旧输出清空；回滚与终态判定在 InnoDB 行锁上串行 |
| 新 claim 开始事务前，取消先提交 | `stale executor calls=1` / `old attempt rows=1` | executor=0，旧 attempt 行=0 |
| 新 claim 开始事务前，取消后回滚先提交 | 同样新增并执行旧 attempt 1 | executor=0，旧 attempt 行=0，新轮不受旧任务影响 |
| 重复投递进入接管前，取消或回滚先提交 | 原有终态 attempt 守卫对照 | executor=0，仅保留取消前已存在且被关闭的证据行 |
| claim 已读快照，取消后到 | 去掉 FOR UPDATE 的 overlay 变异使 `cancel committed between claim snapshot and attempt insertion` | 取消等待认领提交，再正常关闭已认领 attempt |
| 接管资格读失败 | 防止沿心跳“尽力”分支放行 | 返回错误及 id=0 |
| 终态补判的租约已失冠 | 新增 fence 断言 | ErrFenced，零终态写入 |

测试位置：`internal/scheduler/finish_race_test.go`、`internal/worker/claim_race_test.go`、`internal/scheduler/fence_test.go`。`internal/db/sqltest/intercept.go` 只暂停真实 MySQL 驱动边界，保留预备语句、事务与 InnoDB 锁，不在生产逻辑注入测试钩子。锁等待由 `performance_schema.data_lock_waits` 观测，不用固定 sleep 猜测交错。
